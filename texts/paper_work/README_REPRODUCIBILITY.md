# GO-3055 article: reproducibility guide

This is the technical companion to `go3055_jwst_sbf_article_draft.tex`.
The printed appendices keep the scientific diagnostics and processing configuration;
file lists and execution commands are retained here. Repository-relative paths are used below.

## Existing products: regenerate figures and PDF only

Run from `code/` with the project environment already active. These commands
do not repeat galaxy modelling or SBF measurements. The figure builder reads
completed calibration tables and preserves their fitted values.

```bash
py build_go3055_article_figures.py
latexmk -cd -pdf -outdir=build -interaction=nonstopmode -halt-on-error ../texts/paper_work/go3055_jwst_sbf_article_draft.tex
```

The PDF and all LaTeX auxiliary files are in `texts/paper_work/build/`.
The figure builder also retains some diagnostic plots that are intentionally not
included in the printed article; generating a file does not make it a paper figure.
The three main calibration panels show adopted one-sigma color errors and
absolute-SBF measurement errors. Their grey strips show fitted intrinsic scatter,
not confidence intervals for the fitted line.

## Analysis stages

The galaxy modelling and source-mask notebook is `code/sbf-2.ipynb`; its dedicated GO-3055 runner is `code/run_sbf_2_batch.py`.  The final normalized-full spectral branch is implemented in `code/sbf2_normalized_winsor_core.py` and executed sequentially by `code/run_sbf_2_normalized_winsor.py`.  It reuses the saved galaxy model, masks, PSFs, annular geometry, and cached $E(k)$ rather than repeating isophotal modelling.  Exploratory fits and diagnostic figures are generated and displayed inline by `code/sbf-2-graph.ipynb`, which reads completed batch products and does not repeat the SBF measurement. The three-galaxy winsorization, noise, and 129-versus-257-pixel PSF diagnostics are generated by `code/sbf-2-systematics.ipynb`.  The all-galaxy spectral-branch comparison is summarized in `code/sbf-2-normalized-winsor.ipynb`; its synthetic recovery is implemented by `code/sbf2_normalized_winsor_recovery.py`.  The adopted constant-calibration tables, distance-recovery figures, error-budget figure, comparison tables, and provenance records are generated from those saved products by `code/build_sbf2_article_tables.py`. The F090W measurement is run by `code/run_sbf_f090w.py`; its calibration, model comparisons, LOO distances, and inline figures are generated by `code/sbf-f090w-graph.ipynb`, whose reproducible source builder is `code/build_sbf_f090w_graph_notebook.py`.

The article-specific figure renderer is `code/build_go3055_article_figures.py`.
It reads the saved fits; it is separate from the notebooks' interactive figures.

## Full reprocessing, only when required

The following are distinct stages, not a requirement for rebuilding the PDF.
Measurement runners use their status files and caches. Executing notebooks
recomputes analysis outputs and overwrites their displayed results; inspect
their configuration before execution. No notebook was executed for the
2026-09-05 appendix and color-error-bar revision.

Run from `code/` in the active project environment:

```bash
py run_sbf_2_batch.py --no-download --no-cleanup-inputs
py run_sbf_2_normalized_winsor.py --stop-on-error
py sbf2_normalized_winsor_recovery.py
py run_sbf_f090w.py
jupyter nbconvert --to notebook --execute --inplace sbf-2-graph.ipynb --ExecutePreprocessor.timeout=7200
jupyter nbconvert --to notebook --execute --inplace sbf-f090w-graph.ipynb --ExecutePreprocessor.timeout=7200
py build_sbf2_article_tables.py
py build_go3055_article_figures.py
latexmk -cd -pdf -outdir=build -interaction=nonstopmode -halt-on-error ../texts/paper_work/go3055_jwst_sbf_article_draft.tex
```

The three-target exploratory notebook `code/sbf-2-systematics.ipynb` is separate;
it is not required to regenerate the adopted distance tables from existing products.
The script/notebook-specific setup instructions remain authoritative for rebuilding
their diagnostic input caches.

## Provenance

`runs/sbf2_go3055/analysis/tables/go3055_software_provenance.csv` retains
full software versions, Git identifiers and SHA256 file checksums.
The printed software table intentionally omits SHA256 rows but keeps Git revisions,
versions and the adopted processing contract. The CSV must not be confused with
proof that an old product was generated by the current working-tree source:
some entries explicitly identify current source rather than executed snapshots.

Input pipeline and CRDS context combinations are recorded in
`runs/sbf2_go3055/analysis/tables/go3055_input_calibration_provenance.csv`.
The article describes the heterogeneous archive reductions rather than claiming a
uniform local JWST reduction.
