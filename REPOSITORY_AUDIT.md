### Почему `.git` больше текущих файлов

`git count-objects`: примерно 953.61 MiB loose-объектов и 156.67 MiB в pack.
Это не означает, что loose-объекты можно удалять: среди них обычная история.

- В истории HEAD содержимое blob занимает 882.36 MiB до сжатия.
- Ещё 11.15 MiB содержимого удерживаются только другими refs. Поэтому удаление
  одних backup/rescue-веток не устранит основную историю.
- Старые `runs/sbf3_go3055_go7763/products/` занимают суммарно 299.19 MiB
  исторических blob, хотя самих этих путей в HEAD уже нет.
- История notebook — 253.38 MiB; из них 201.99 MiB — девять версий одного
  `sbf-2-graph.ipynb`. История PDF в `texts/` — 105.83 MiB.
- Вне refs, но доступные через reflog: 28 blob, около 266.75 MiB хранения
  объектов; в основном старые `.npz` нормировочного эксперимента.
- Вне refs и reflog: ещё 315 blob, около 413.62 MiB хранения объектов.
  Это потенциальные данные восстановления; их происхождение по путям не
  установлено, поэтому они не объявлены безопасно удаляемыми.

Размеры `objectsize:disk` не включают весь overhead Git и не являются обещанием
столько же освободить. Ни `gc`, ни `prune`, ни `repack`, ни истечение reflog,
ни переписывание истории не выполнялись.

Порядок будущей работы с Git: сохранить резервную копию, согласовать untracking,
проверить нужные точки восстановления, затем отдельно решать вопрос упаковки
или очистки истории. Для чистого source release можно создать отдельный
компактный экспорт, не переписывая исследовательскую историю.

## 5. Готовность воспроизводимого релиза

**Локальные принятые продукты доступны, но обещание «чистый clone → тот же

14 F150 normalized JSON, 14 F090 products JSON, 14 F090 source JSON,
14 F090 final JSON и обеих master CSV: отсутствующих локальных целей не найдено.
Это проверка существования путей, не проверка содержимого всех FITS.

Все 28 исходных GO-3055 i2d FITS существуют, их суммарный объём — 31.68 GiB.
Но есть следующие блокеры переносимости:

1. **Абсолютные пути.** CSV/JSON и часть кода используют текущий путь
   `/Users/zuha/.../course_work-SBF`. Ключи некоторых кэшей зависят также от
   размера и `mtime_ns`; перенос может вызвать повтор расчёта.
2. **Окружение не закреплено.** Полного актуального lock/environment-файла нет;
   старый `baseline_environment.txt` не обеспечивает установку нынешнего стека.
3. **Внешние STPSF reference data.** Используется
   `/Users/zuha/data/stpsf-data`, версия reference data 2.1.0. Одного clone
   недостаточно; нужны конкретные OPD и версии reference data.
4. **Manifest не фиксирует использованные байты.** Для 24 из 28 i2d локальный

   порчи FITS, но URL и старого размера недостаточно для точного воспроизведения.
5. **Current source != executed source.** Сохранённый
   `runs/sbf2_go3055/campaign/input_contract_snapshots/sbf-2__a1828d2d8d97.ipynb`
   отличается от текущего notebook не только outputs: есть изменения поглощения,

Минимальный выпуск состоит не из одной папки со скриптами, а из трёх частей:

| Часть | Содержимое |
|---|---|
| Исходники | Активный код из раздела 2, configs/manifests, справочные CSV и визуальные оценки, tests, зафиксированное окружение, инструкция; выбранная исполняемая версия и provenance |
| Архив воспроизведения | Принятые CSV/JSON полной точности, необходимые FITS/маски/PSF/каталоги, научные журналы, snapshot/generated notebook, reference-data manifest; большие файлы вне обычной истории Git |
| Выпускные результаты | Контрольные таблицы двух фильтров, рисунки, выполненные notebook/HTML и PDF, версии и ожидаемые численные допуски |

Для каждого файла архива нужны относительный путь, назначение, фильтр/галактика,
источник, размер, контрольная сумма и информация о том, каким кодом/настройками
он получен. Для симлинков — переносимая цель либо реальный файл в архиве.
Полные контрольные суммы многогигабайтных FITS в этом быстром аудите не считались.

Не включать в минимальный GO-3055 source release: виртуальное окружение,
временные рендеры, сборочный мусор, текущие блокировки/операционные SQLite,

архивы при этом сохраняются, а нужные campaign/provenance данные включаются

## Источники и ограничения аудита

Проверены файловые размеры, tracked/ignored списки, refs/reflog/blob-метаданные
Git, текущие manifests и цепочки ссылок принятых продуктов. Зависимости кода
проверялись через codebase-memory (Verify; generation 2026-09-04T01:40:51Z)
с чтением актуальных исходников для изменённых/непокрытых файлов. Пройдены
обе страницы индекса `code/* File`; охват графа не считается доказательством
отсутствия зависимостей, особенно для notebook и сгенерированных файлов.

Основные исходники для существенных выводов: `run_sbf_2_batch.py`,
`run_sbf_f090w.py`, `sbf2_normalized_winsor_core.py`,
`build_sbf_f090w_graph_notebook.py`, `build_go3055_article_figures.py`,
`build_sbf2_article_tables.py`, `sbf2_normalized_winsor_recovery.py` и README
существующего legacy-архива. Это аудит готовности и сохранности, не новый
научный прогон и не исчерпывающее доказательство мёртвого кода.
