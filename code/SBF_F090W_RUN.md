# GO-3055: прогон SBF в F090W

Основной вход — `run_sbf_f090w.py`. Это отдельный офлайн-пайплайн: готовый
F150W-анализ и `sbf-2.ipynb` он не изменяет.

## Что считается

- сигнал SBF: F090W;
- F150W пока только проверяется как локальный вспомогательный вход, но не
  загружается в память; цветовая калибровка в этот прогон не входит;
- геометрия колец: 8.2–16.4 и 16.4–32.8 arcsec;
- центр переносится через WCS из принятой F150W-модели, затем допускается
  только локальное уточнение F090W в радиусе 250 px; глобальный яркий объект
  больше не может увести центр галактики;
- изофоты перебирают стартовые радиусы 40, 50, 60, 70 и 100 px: сначала
  короткий пробный fit, затем один полный fit, который обязан дойти до
  внешнего рабочего кольца;
- Sérsic-модель F090W задаёт только стартовые эллиптичность и угол; в самом
  подборе они остаются свободны;
- пробные старты ранжируются по сходимости и гладкости, а не по величине стартового
  радиуса; плохая полная ветвь отклоняется, после чего пробуется следующая;
- единый контроль для всех 14 целей проверяет несошедшиеся (`stop_code=2`),
  замороженные (`stop_code=1,4,5`) и сингулярные (`stop_code=3`) изофоты,
  скачки центра, комплексной эллиптичности и рост яркости наружу внутри двух
  научных колец;
- крупные компоненты маскируются по одному правилу для всей выборки: источник
  должен быть ярче `S/N=100` и целиком лежать дальше 250 px от центра; поэтому
  звезда NGC 1399 закрывается, а центральные структуры галактик сохраняются;
- остаток: `(SCI - background - model) / sqrt(model)`;
- общий порог 3.5 sigma определяется по всей валидной положительной области
  модели уже после нормировки;
- спектр: `P(k) = P0 E(k) + P1`, `kmin = 0.01, 0.03, 0.04`, основной
  результат при `kmin=0.04`, `kmax=0.25`;
- PSF: отдельный F090W STPSF-ансамбль 129×129, ближайший WSS OPD и четыре
  смещения по детектору. Это фактический центрированный вариант прежнего
  названия «PSF-128».

F150W PSF и `E(k)` для F090W не переиспользуются.

## Проверка без расчёта

Все команды пользователь запускает из каталога `code` при активированном
`astro_env`:

```bash
py run_sbf_f090w.py --dry-run
```

Dry run открывает заголовки локальных FITS, проверяет фильтры, STPSF и покрытие
OPD. Сеть не используется. На 2026-09-01 все 14 пар F090W/F150W локальны и
готовы; докачка не нужна.

## Полный запуск

Из `code` в активированном окружении:

```bash
py run_sbf_f090w.py
```

Для короткой проверки одной цели:

```bash
py run_sbf_f090w.py --galaxies "NGC 3379"
```

## Остановка и продолжение

Обычный повтор той же команды продолжает очередь. Готовые цели повторно не
считаются. Публичный журнал — простая таблица:

`runs/sbf_f090w_go3055/target_status.csv`.

В ней нет SHA: только галактика, статус, этап, номер попытки, время, сообщение,
PID активного процесса и пути к результатам. Если процесс был жёстко
остановлен, мёртвая строка `running` на следующем запуске становится
`interrupted`. Если дочерний процесс ещё жив, строка остаётся `running`, а
второй экземпляр runner не запускается, чтобы не писать в те же FITS.

Полный журнал кампании лежит в `campaign.log`, а отдельные журналы галактик и
времена выполнения ячеек — в `logs/` внутри того же каталога запуска.
Каждая физическая строка в консоли и журналах имеет префик
`[ЧЧ:ММ:СС, NGC XXXX, N/14]`. Для общих сообщений до и после очереди
используется `[ЧЧ:ММ:СС, campaign, 0/14]`.

Кэшируются:

- завершённая модель/маска/каталог и `P_r`;
- F090W PSF после атомарной проверки;
- компактные FFT-входы;
- Monte-Carlo `E(k)`;
- полностью завершённая галактика.

Если остановка пришлась внутрь построения изофот, текущая галактика начнёт
этот этап заново. Уже записанный и проверенный PSF подхватится. Если модельный
этап закончен, повторится только незавершённая спектральная часть. Текущая
операция `E(k)` атомарна: недописанный кэш не принимается.

## Продукты

Для каждой цели создаётся каталог
`runs/sbf_f090w_go3055/products/NGC_XXXX/` с понятными ссылками без дублирования
многогигабайтных FITS:

1. `*_01_model.fits` — full-frame модель F090W;
2. `*_02_normalized_full_clip_3p5sigma.fits` — полный нормированный и
   винзорированный остаток до покольцевого вычитания среднего;
3. `*_03_normalized_inner_fft_input.fits` — точный вход FFT внутреннего кольца;
4. `*_04_normalized_outer_fft_input.fits` — точный вход FFT внешнего кольца;
5. `*_05_psf_129.fits` — проверенный ансамбль F090W PSF;
6. `*_f090w_sbf_summary.csv` — краткий результат одной галактики.

После нового модельного расчёта рядом публикуются ещё четыре диагностические
таблицы: принятый центр, все попытки запуска изофот, все принятые изофоты и
решения по крупным внешним загрязнителям.
Все цели GO-3055 без этих таблиц считаются устаревшими и один раз пересчитываются по единой
схеме. После этого обычный повтор команды пропускает каждую уже завершённую галактику.

Файлы колец имеют `PRIMARY` для просмотра, `FFTINPUT` с точным численным
массивом и `WINDOW` с бинарной рабочей маской.

Общая таблица:

`runs/sbf_f090w_go3055/f090w_sbf_results.csv`.

Она содержит наблюдаемые и исправленные за `A_F090W` величины внутреннего,
внешнего и объединённого результата, их ошибки и доли изменённых пикселей.
Только эта человекочитаемая таблица округляется до трёх знаков после запятой;
внутренние спектральные таблицы сохраняют полную точность.

Записанные `sigma_*_internal` — внутренние измерительные ошибки спектрального
фита с разбросом по PSF и окнам `k`; для объединённого результата также
учитывается различие колец. Поля `sigma_*_0` дополнительно включают ошибку
галактического поглощения. Это ещё не полный систематический бюджет будущей
абсолютной F090W-калибровки.

## Место на диске

Ожидаемый объём новой кампании — около 50 GB: модельный notebook сохраняет
полноразмерные промежуточные FITS, как и F150W. Перед каждой новой галактикой
runner проверяет свободное место и по умолчанию безопасно останавливается при
остатке менее 20 GB. Порог можно явно изменить, например:

```bash
py run_sbf_f090w.py --min-free-gb 10
```

После освобождения места повторяется обычная команда; готовые цели не
пересчитываются.

## Принудительный пересчёт

Обычному запуску эти ключи не нужны:

- `--force-source` — заново модель/маска/PSF-этап;
- `--force-spectra` — заново спектральный этап;
- `--rebuild-psf` — удалить и построить PSF текущих выбранных целей;
- `--rebuild-input-cache` — заново компактный FFT-кэш;
- `--rebuild-expectation-cache` — заново `E(k)`.

Размер 129 принят для основного прогона ради сопоставимости с F150W. Перед
финальной абсолютной калибровкой F090W отдельно потребуется проверка 129 против
257 хотя бы на нескольких характерных объектах; она не блокирует этот прогон.

## История первого F090W-прогона (команду ниже больше не использовать)

Три цели (`NGC 1549`, `NGC 4621`, `NGC 4697`) упали из-за неверного
глобального центра и сами требуют нового модельного этапа. У `NGC 1399`
старый результат формально завершён, но валидатор сам назначит ей одноразовый
пересчёт: яркая звезда площадью 8382 px была отброшена старым пределом
5000 px и испортила изофоты. Новый шаблон единым для всех целей правилом
сохраняет яркие внешние компоненты в отдельной маске и переносит её в конечный
FFT-вход. Геометрический QC отклоняет
плохой полный fit и продолжает перебор, а не публикует первый формально непустой результат.

Из каталога `code` достаточно одного точечного запуска:

```bash
py run_sbf_f090w.py --galaxies \
  "NGC 1399" "NGC 4697" "NGC 4621" "NGC 1549"
```

Для старого результата NGC 1399 валидатор сам требует новую схему маски; флаг
`--force-source` не нужен. После прерывания повторяется ровно та же команда:
уже законченные цели будут пропущены, текущая продолжит с последнего полностью
завершённого этапа. Остальные десять целей эта команда не запускает.
После прогона нужно глазами проверить внешнюю маску и остаток NGC 1399:
универсальное правило технически закрывает известную звезду, но научную
пригодность маски нельзя доказать одним валидатором.

## Актуальный единый пересчёт

У NGC 4697 прежний код при равных пробных результатах выбрал старт 100 px. Затем он
принял 37 несошедшихся изофот подряд и сшил ложную круглую внутреннюю ветвь с правильной
внешней. Теперь все 14 целей проходят один и тот же контроль.

Сначала из каталога `code` пересчитывается только NGC 4697:

```bash
py run_sbf_f090w.py --galaxies "NGC 4697"
```

Старая схема автоматически признаётся устаревшей, поэтому `--force-source`
не нужен. При прерывании повторяется ровно та же команда. После успеха нужно
глазами проверить модель, полный остаток и CSV изофот: круглая
внутренняя ветвь и скачок на 630--640 px должны исчезнуть.

После визуального подтверждения обычный запуск пересчитает остальные 13 целей:

```bash
py run_sbf_f090w.py
```

NGC 4697 будет пропущена как уже готовая по той же версии метода; прежние 13 результатов будут
отклонены новой схемой. В итоге все 14 будут обработаны одинаково, без повторного пересчёта
уже исправленной NGC 4697.
