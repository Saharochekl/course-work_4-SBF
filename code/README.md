# Рабочий код GO-3055

Команды ниже запускаются **из `code/`**, в уже активированном `astro_env`, через `py`.
Активная научная схема — F150W без цветового члена и F090W с линейной цветовой
калибровкой, по всем 14 галактикам. Пересчёт не требуется для изменения цвета линий.

## Что запускать

| Этап | Входная точка |
|---|---|
| Скачать/проверить исходные JWST i2d | `download_go3055_go7763.py` и `targets_go3055_manifest.csv` |
| Подготовить WSS OPD для PSF | `download_wss_opds.py` |
| Модель, маски, исходные продукты F150W | `run_sbf_2_batch.py` → `sbf-2.ipynb` |
| Принятые нормированные F150W-спектры | `run_sbf_2_normalized_winsor.py` → `sbf2_normalized_winsor_core.py` |
| Измерения F090W | `run_sbf_f090w.py` → общее ядро и `sbf090_pipeline_support.py` |
| Калибровки, расстояния, интерактивные графики | `sbf-2-graph.ipynb`, `sbf-f090w-graph.ipynb` |
| Проверки PSF/шума/винзорирования | `sbf-2-systematics.ipynb`, `sbf-2-normalized-winsor.ipynb`, recovery/summary scripts |
| Таблицы статьи | `build_sbf2_article_tables.py` |
| Рисунки статьи из готовых измерений | `build_go3055_article_figures.py`; отдельные montage/appendix builders |
| Синхронизировать готовые картинки со статьёй | `publish_article_assets.py` |
| Проверить структуру без расчёта галактик | `check_project_layout.py --with-products` |

Обработчик F090W, его support-модуль и оба загрузчика **отслеживаются Git**.
Игнорируется большой каталог результатов `runs/sbf_f090w_go3055/`, а не код.

## Быстрая проверка после переноса проекта

```bash
py check_project_layout.py --with-products
py publish_article_assets.py --check
```

Первая команда проверяет синтаксис Python и notebook, существование выбранных
продуктов обоих фильтров и публикационные изображения. Ячейки не выполняются,
массивы FITS не открываются. Без локальных научных данных можно убрать
`--with-products`; это проверит только код и сохранённые материалы статьи.

## Скачать данные — отдельное действие

```bash
py download_go3055_go7763.py --program 3055
```

Без `--download` это проверка наличия, не загрузка. Для реального скачивания
нужно явно добавить `--download`. Без `--program 3055` загрузчик по умолчанию
рассматривает также GO-7763. OPD готовятся отдельным загрузчиком; установка
reference data STPSF не подменяется загрузкой i2d.

Полные измерительные команды и ограничения приведены в `SBF_F090W_RUN.md`,
`SBF2_NORMALIZED_WINSOR.md` и `../texts/paper_work/README_REPRODUCIBILITY.md`.
Не запускайте полный batch только для пересборки PDF.

## Пути и рисунки

`sbf_paths.py` определяет корень по расположению кода. Пути вида `data/...`,
`runs/...` разрешаются относительно этого корня. Старые записи
`/.../course_work-SBF/runs/...` читаются из текущей копии проекта даже при
сохранённой старой копии. Исторические JSON/CSV и журналы на диске не переписываются.
Для новых вызывающих функций доступен `portable_path()`; некоторые старые
производители всё ещё записывают абсолютные runtime-пути, которые читает resolver.

Данные STPSF выбираются через `STPSF_PATH`, локальный `data/stpsf-data/` или
существующую внешнюю домашнюю установку. Внешние файлы не превращаются молча
в несуществующие файлы внутри репозитория.

Публикационные рисунки находятся в `../texts/paper_work/materials/figures/`.
Явное соответствие исходников и публикационных файлов — `materials/figure_sources.json`.
Выбранные figure-builders и функции сохранения основных graph-notebook обновляют
эти копии после перерисовки. Прямые/старые сохранения можно синхронизировать командой
`py publish_article_assets.py`. Исходные рисунки в `runs/` сохранены для анализа.

## Что не является активным кодом

- `legacy/review-2026-09-08/sbf3/` — SBF-3, мониторинг и тесты расширенной кампании.
- `legacy/review-2026-09-08/analysis/` — старые инструменты курсовой.
- `legacy/review-2026-09-08/catalog_search/` — поиск расширенной выборки.
- Старые научные запуски — `../runs/legacy/review-2026-09-08/`.

Литературные входы `sbf2_batch_outputs/`, тесты, runtime-модули и сохранённые
научные кэши не удалять. По некоторым старым путям данных оставлены относительные
совместимые ссылки; они не занимают второй экземпляр данных.

## Границы проверки

Сводка ревью — `../REVIEW_CHANGES.md`. Полного научного прогона с нуля в этой
ревизии не было. Сохранение существующих кэшей проверено в текущей копии;
на другой файловой системе их защитные fingerprints могут потребовать перестроения.
Два старых `LegacyGo3055AdoptionTests` зависят от уже отсутствующих исторических
FITS: это известная неполнота старого архива, не тест принятой F150W/F090W-калибровки.
