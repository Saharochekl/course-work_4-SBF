# Проверка обрезки после нормировки

Production-пайплайн `sbf-2.ipynb` не изменяется. Эксперимент читает его
завершённые продукты и повторяет только нормировку, FFT, построение `E(k)` и
фит `P(k)=P0 E(k)+P1`.

## Ветви

| Ветвь | Порядок | Назначение |
|---|---|---|
| `no_winsor` | `raw / sqrt(model)` | Jensen-like baseline |
| `raw_global_3p5` | raw 3.5σ, затем нормировка | замыкание на production |
| `normalized_full_3p5` | нормировка, затем 3.5σ по всей модели | чистый тест порядка |
| `normalized_union_3p5` | нормировка, затем 3.5σ по двум кольцам | основной кандидат |

Один порог `normalized_union_3p5` оценивается по объединению двух колец и
применяется к ним обоим. Раздельные пороги запрещены: они искусственно
сближали бы кольца.

«Обрезка» во всех ветвях означает винзорирование: значения прижимаются к
границе, но рабочая маска не меняется. Поэтому один и тот же `E(k)` допустим
для всех ветвей.

## Кэш

Первый проход создаёт два независимых кэша:

- `cache/inputs` — компактные crops точного `SCI-background-model`, модели,
  окон колец и PSF;
- `cache/expectation` — per-PSF профили `E(k)` для неизменных окон.

Ключ учитывает входные файлы, параметры FFT, seed и число реализаций. Смена
только sigma не пересчитывает `E(k)`. Старые production-файлы не изменяются.
Для NGC 3379, NGC 1380 и NGC 4486 код умеет импортировать уже рассчитанные
per-PSF `E(k)` из `sbf2_systematics`, но только после полного совпадения
fingerprint входов и успешного production-closure.

## Остановка и повторный запуск

Состояние очереди лежит в обычной таблице
`runs/sbf2_normalized_winsor/batch/target_status.csv`. В ней нет SHA:
есть имя галактики, статус, текущий этап, номер попытки, время и
сообщение.

Повторный запус:

- сразу пропускает галактики со статусом `ok`, если их таблицы и FITS
  действительно читаются;
- повторно использует целый input-cache;
- повторно использует целый кэш $E(k)$;
- повторяет текущий этап, если он был оборван до атомарной записи.

Внутри одного расчёта $E(k)$ промежуточные PSF пока не сохраняются. Если
оборвать посреди этого этапа, $E(k)$ для текущей галактики будет повторён
целиком. Завершённые галактики при этом не затрагиваются.

## FITS-контракт

По умолчанию для каждой галактики пишется один обычный двумерный
float32 FITS полного размера:

`<stem>_sbf_resid_catalog_mask_normalized_clip_3p5sigma.fits`.

Его значения построены как

\[
q = \operatorname{winsor}_{3.5\sigma}
\left(\frac{SCI-B-M}{\sqrt{M}}\right).
\]

Уже применена окончательная catalog-mask; вне неё, в щелях детектора и вне
положительной модели стоит `NaN`. Кандидатная ветвь берёт пиксели колец именно
из этого float32-массива. FITS является численным продуктом, а не декоративной
визуализацией.

В FITS ещё не вычтено среднее: оно разное для inner и outer колец. Поэтому после
сохранения остаются ровно три измерительные операции: выбрать кольцо, вычесть его
среднее и выполнить FFT/фит $P(k)$.

Кадр 4377x9876 занимает около 173 МБ, то есть около 2.4 ГБ для 14 целей.

Тяжёлые покольцевые multi-HDU FITS по умолчанию отключены. Опция
`save_ring_fft_fits=True` сохраняет их для основного кандидата, а
`save_all_branch_fits=True` -- для всех ветвей. В таком диагностическом FITS:

- `PRIMARY`: float32-визуализация кольца, `NaN` вне окна;
- `FFTINPUT`: точный float64-массив для FFT, нули вне окна;
- `WINDOW`: бинарная маска.

## Порядок решения

1. Старая ветвь должна замкнуться на production: `|Δmbar| <= 0.005 mag` и
   `|ΔP0/P0| <= 0.5%`.
2. Для кандидата требуется `P0-Pr > 0` для обоих колец и всех PSF.
3. Проверяется размах по `kmin=0.01, 0.03, 0.04`; ориентир — не более
   `0.03 mag`.
4. Расхождение колец не должно ухудшиться более чем на `0.02 mag` относительно
   ветви без винзорирования. Это диагностика, а не требование равенства колец.
5. Доли изменённых пикселей inner/outer публикуются. Перекос больше одного
   процентного пункта помечается, но сам по себе ничего не доказывает.
6. До принятия новой ветви обязателен injection-recovery: целевой bias меньше
   `0.01 mag`, `|bias| > 0.02 mag` означает отказ.
7. Финальный выбор делается только после сравнения всех 14 галактик по
   нуль-пункту, intrinsic scatter и LOO RMS. Совпадение с ожидаемым расстоянием
   отдельной галактики не является критерием.

Пер-кольцевые `mbar` в эксперименте остаются наблюдаемыми, как в `df_sbf`.
Поправка `A_F150W` должна применяться одинаково уже при калибровке всех 14;
в разностях между ветвями она сокращается.

Основной интерактивный вход — `sbf-2-normalized-winsor.ipynb`. Для
последовательного прогона целей используется `run_sbf_2_normalized_winsor.py`.

## Перезапуск

Единственная таблица состояния очереди —
`runs/sbf2_normalized_winsor/batch/target_status.csv`. В ней нет хэшей: для
каждой галактики записаны понятные поля `status`, `stage`, номер попытки, время
начала и окончания, сообщение об ошибке и путь к результату.

Статус `ok` принимается только при наличии читаемых итоговых таблиц и FITS,
соответствующих текущим настройкам и production-входу. Такие галактики при
повторном запуске переиспользуются. `running`, оставшийся после жёсткой
остановки, автоматически превращается в `interrupted`.

Текущая галактика не продолжается с произвольного места внутри FFT: её
спектральный этап запускается заново. Уже полностью и атомарно записанные
входной кэш и кэш `E(k)` переиспользуются. Недописанный временный файл итоговым
не считается. Ключ `--force` намеренно пересчитывает цель независимо от
таблицы.

Внутренние служебные ключи остаются только для разделения несовместимых
численных кэшей; они не являются пользовательским журналом выполнения и в
`target_status.csv` не записываются.
